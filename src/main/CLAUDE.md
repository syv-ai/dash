# Main process

- **Task sessions** run under Claude Code's supervisor (`claude --bg`); Dash only attaches. A session runs in a pre-spawned process, so the launch command's env never reaches it: anything it needs goes in the task's settings file (`taskSettings.ts`, rewritten every start, re-read on respawn).
- **Hooks** (`ptyHookSettings.ts`): an unknown hook key makes Claude Code drop the whole file, so gate any event newer than `MIN_CLAUDE_VERSION` with `isClaudeVersionAtLeast`.
- **Control API** (`control/`): `scope.ts` is the only gate for who sees what; don't scope-check in handlers. Task lifecycle (create/archive/restore/delete, project delete) goes through `TaskService`.
- **Claude Code contract** (`claudeContract/`): every place Dash reads Claude Code (a hook payload, the statusLine, CLI output or exit codes, its internal files) has a schema there and reports drift through `reportFindings`/`reportDrift`; a new integration gets both. Validation only watches: on a mismatch Dash does what it did, plus a report, and it never throws into the hook path. Facts about Claude Code come from the current docs (code.claude.com/docs) and a live payload log, not memory. Drift is logged to `<userData>/claude-drift.jsonl` (`Dash-dev/` for a dev run; one record per version, source, kind and path, with first/last seen and a count; rotated to `claude-drift.1.jsonl`), printed once per run as `[claude-drift]` on stderr, and sent to PostHog once per key as `claude_contract_drift`.
